# Attractor Runtime Requirements

Source: [`docs/upstream/strongdm-attractor/attractor-spec.md`](../../../upstream/strongdm-attractor/attractor-spec.md)

Status values are `proved`, `partial`, `missing`, or `deferred`. “Proved” means the repository has automated behavior evidence at the required seam; it does not imply live-provider parity.

| Story | Status | Requirement and acceptance proof |
|---|---|---|
| ATTR-DOT-01 | proved | Parse the strict DOT subset: graph/node/edge attributes, comments, quoted and unquoted values, chains, defaults, and subgraphs ([§2.1–2.12](../../../upstream/strongdm-attractor/attractor-spec.md#2-dot-dsl-schema)). `SCN-ATTR-PARSE` exercises the currently proved parser contract. |
| ATTR-DOT-02 | proved | Apply graph, node, edge, timeout, fidelity, and thread attributes with correct inheritance. Covered by parser/parity tests. |
| ATTR-DOT-03 | partial | Derive a stylesheet class from every subgraph label regardless of whether the label precedes or follows its nodes ([§2.10](../../../upstream/strongdm-attractor/attractor-spec.md#210-subgraphs)). `SCN-SUBGRAPH-LABEL` is the missing label-after-node regression. |
| ATTR-ENG-01 | proved | Traverse nodes and select edges deterministically, including preferred labels, suggested IDs, conditions, goal gates, and failure routing. `SCN-ATTR-ENGINE`. |
| ATTR-ENG-02 | proved | Enforce inherited and explicit per-attempt deadlines, retries, cooperative cancellation, timeout events, and partial-output preservation. `SCN-TIMEOUT`. |
| ATTR-ENG-03 | partial | Provide one public DOT-source lifecycle in `attractor.pipeline`: `prepare` performs parse → built-in transforms → caller-supplied custom transforms → validation and returns `{:graph prepared-graph :diagnostics [...]}` without execution; `run` calls `prepare`, then continues through initialization, raw execution, and finalization ([§3.1](../../../upstream/strongdm-attractor/attractor-spec.md#31-run-lifecycle), [§7.3](../../../upstream/strongdm-attractor/attractor-spec.md#73-validation-api), [§9.1](../../../upstream/strongdm-attractor/attractor-spec.md#91-ast-transforms)). Both accept ordered `:custom-transforms` and `:custom-rules`; `run` also accepts the existing registry/context/log/event engine options. If diagnostics contain ERROR, `run` throws category `:validation_error` with `:diagnostics` before creating execution state; otherwise its returned outcome includes the warning/info `:diagnostics`. CLI run and server submission use `run`; CLI validate/graph use `prepare`. `attractor.engine/run-pipeline` remains the explicitly documented low-level, already-prepared-graph API. `SCN-PUBLIC-LIFECYCLE` and `SCN-ATTR-ENGINE`. |
| ATTR-ENG-04 | partial | Resolve the upstream conflict between §3.5 (returned FAIL is terminal) and the Definition of Done (FAIL may retry), document the chosen contract, and lock it with a regression. Current behavior follows §3.5. |
| ATTR-ENG-05 | partial | `loop_restart=true` emits `pipeline.restarting` with old root, new root, and target before the target stage starts, then re-enters at that target under a distinct run-log root ([§2.7](../../../upstream/strongdm-attractor/attractor-spec.md#27-edge-attributes), [§3.2](../../../upstream/strongdm-attractor/attractor-spec.md#32-core-execution-loop)). Project-defined preserve/reset matrix: preserve the prepared graph, handler registry, cancellation signal, event sink, and current context values; reset completed nodes, node outcomes, retry counters, fidelity sessions, checkpoint, and per-stage status/artifact state; treat the restart edge as the target's incoming edge. `SCN-LOOP-RESTART`. |
| ATTR-STATUS-01 | done:ITER-0001 | A valid `status.json` written during the current attempt is authoritative for outcome, notes, preferred edge label, suggested node IDs, context updates, and retry routing ([Appendix C](../../../upstream/strongdm-attractor/attractor-spec.md#appendix-c-status-file-contract)). Validate the required outcome enum and every present specified field's type, including string elements in `suggested_next_ids`; malformed current files terminate explicitly, while unknown fields are ignored for forward compatibility. Project resolution of the ambiguity between handler-returned Outcomes ([§4.1](../../../upstream/strongdm-attractor/attractor-spec.md#41-handler-interface), [§5.2](../../../upstream/strongdm-attractor/attractor-spec.md#52-outcome)) and Appendix C: before every main/subgraph retry attempt, remove or ignore stale status; a valid current file beats a conflicting handler return; without a file, accept a valid handler outcome. Pipeline cancellation and attempt timeout remain terminal, and no status file—whether written before cancellation or late after quiescence—can convert them to success/retry. Events, checkpoint, and routing all use the same resolved outcome. `SCN-STATUS-FILE`. |
| ATTR-STATUS-02 | done:ITER-0001 | When neither a current status file nor valid handler outcome exists and `auto_status=true`, synthesize and persist the specification's exact success/note ([Appendix C](../../../upstream/strongdm-attractor/attractor-spec.md#appendix-c-status-file-contract)). Project deterministic interpretation: explicit `auto_status=false` overrides inherited true, and main-run/`execute-subgraph` use identical resolution. `SCN-AUTO-STATUS`. |
| ATTR-CP-01 | proved | Persist and resume checkpoints and artifacts. Project decision: internal persistence remains EDN (`checkpoint.edn` and `.edn` artifacts), with migration reads where useful; explicitly external `status.json` remains JSON. `SCN-CHECKPOINT`. |
| ATTR-CTX-01 | partial | `ctx-snapshot` and `ctx-clone` return serializable deep copies rather than sharing nested containers ([§5.1](../../../upstream/strongdm-attractor/attractor-spec.md#51-context), [§3.8](../../../upstream/strongdm-attractor/attractor-spec.md#38-concurrency-model)). The supported persisted/branch value domain is EDN-round-trippable values; unsupported opaque or mutable reference values fail explicitly with category/path data rather than being silently shared. A clone also copies logs, and mutations applied to a clone's nested values cannot affect its parent or sibling clones. `SCN-CONTEXT-ISOLATION`. |
| ATTR-CTX-02 | proved | Resolve full, truncate, compact, summary, and edge/node/thread fidelity semantics, including safe resume degradation ([§5.4](../../../upstream/strongdm-attractor/attractor-spec.md#54-context-fidelity)). Covered by engine fidelity/session tests. |
| ATTR-ART-01 | partial | Expose artifact lifecycle and threshold backing through pipeline outcomes/manifests, including discoverability of handler-produced artifacts. |
| ATTR-HND-01 | partial | Start, exit, codergen, conditional, tool, parallel, fan-in, manager, and registered custom handlers exist and have direct or engine tests ([§4](../../../upstream/strongdm-attractor/attractor-spec.md#4-node-handlers)). Add one registry-to-engine matrix proving each shape/type dispatches through the engine. `SCN-HANDLER-MATRIX`. |
| ATTR-HUM-01 | partial | Human choices and queue/auto-approve routing are proved ([§6](../../../upstream/strongdm-attractor/attractor-spec.md#6-human-in-the-loop-interviewer-pattern)); add callback, recording, accelerator, default, and answer-shape evidence. `SCN-INTERVIEWERS`. |
| ATTR-HUM-02 | missing | Console questions honor `timeout_seconds` without indefinitely blocking on stdin. `SCN-HUMAN-TIMEOUT`. |
| ATTR-PAR-01 | proved | `wait_all` runs isolated, bounded branches and fans them in once. |
| ATTR-PAR-02 | missing | `first_success` returns when the first branch succeeds, then cancels and joins losers without waiting for their normal completion. `SCN-FIRST-SUCCESS`. |
| ATTR-FANIN-01 | missing | A non-empty fan-in prompt uses an injected LLM ranker; an empty prompt retains deterministic heuristic selection. |
| ATTR-VAL-01 | partial | Basic valid/missing-start-exit/unreachable validation is proved ([§7.1–7.4](../../../upstream/strongdm-attractor/attractor-spec.md#7-validation-and-linting)). Complete canonical diagnostics with required keyword keys `:rule`, `:severity`, and `:message` plus optional `:node_id`, `:edge`, and `:fix`; severities are `:error`, `:warning`, or `:info`. Caller-supplied rules run after built-ins in registration order. Prove `validate`, plus `validate-or-raise` throwing category `:validation_error` with the complete `:diagnostics` vector. Project decision: reachability is ERROR, following normative §7.2 and the Definition of Done; the parity-table orphan WARNING row is treated as an upstream contradiction. Error diagnostics block public lifecycle execution before handlers, while warnings remain returned/observable and allow execution. `SCN-VALIDATION`. |
| ATTR-STYLE-01 | proved | Stylesheet selectors, specificity, inheritance, and explicit node overrides work. |
| ATTR-XFORM-01 | partial | Caller-supplied transforms are registered as an ordered vector on the public lifecycle, run after built-ins in registration order, and each receives the prior transform's graph ([§9.1](../../../upstream/strongdm-attractor/attractor-spec.md#91-ast-transforms), [§9.3](../../../upstream/strongdm-attractor/attractor-spec.md#93-custom-transforms)). Direct `attractor.transforms/apply-transforms` calls must leave their caller-owned parsed-graph argument structurally unchanged, while returning the transformed graph; public lifecycle validation observes that returned graph. `SCN-TRANSFORM-ORDER`. |
| ATTR-COMPOSE-01 | partial | Upstream §9.4 requires sub-pipeline execution and graph merging but does not prescribe context mapping ([§9.4](../../../upstream/strongdm-attractor/attractor-spec.md#94-pipeline-composition)). Project-defined extension: a `subpipeline` node names a prepared child DOT source and declares `input_map` and `output_map` objects from parent key to child key and child key to parent key. Missing mapped inputs fail before child execution; duplicate destination keys are validation errors; unmapped parent values never enter the child; child outputs are applied only after SUCCESS/PARTIAL_SUCCESS; FAIL/CANCELLED propagate without output application. Parent and child have separate contexts, run-log roots, checkpoints, completed nodes, outcomes, retries, and fidelity sessions; both pass through the public lifecycle. `SCN-PIPELINE-COMPOSITION`. |
| ATTR-SERVER-01 | partial | Pipeline endpoints, cancellation, questions, checkpoint/context, and graph work; `/events` must remain connected and deliver later events as real SSE. `SCN-SSE-LIVE`. |
| ATTR-OBS-01 | partial | Emit ordered pipeline, stage, checkpoint, parallel, and interview event families with timeout/failure detail. |
| ATTR-HOOK-01 | missing | Run `tool_hooks.pre` and `.post` around every LLM tool call. A failing pre-hook skips execution; a failing post-hook preserves the tool result while recording the failure. `SCN-TOOL-HOOKS`. |
| ATTR-COND-01 | proved | Parse, validate, and evaluate equality/inequality, conjunction, literals, and outcome/context variable resolution ([§10](../../../upstream/strongdm-attractor/attractor-spec.md#10-condition-expression-language)). Covered by condition and routing tests. |
| ATTR-SMOKE-01 | partial | The deterministic mock smoke proves the complete local journey; add an opt-in credential-gated real-provider smoke with the same assertions. `SCN-ATTR-SMOKE-LIVE`. |
