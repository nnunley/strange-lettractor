| ULLM-CANCEL-01 | partial | Cancellation and deadlines interrupt request bodies, stalled responses, and streams promptly while preserving partial output and one terminal outcome. Joined operation ownership is verified (2026-09-08): each `generate`/`stream` operation runs a persistent coordinator (`src/attractor/operation_owner.lg`) that owns the child scope for demanded provider calls and lazy reads, atomically elects the terminal cause (local abort/timeout beats consequent transport errors), closes registered bodies, drains and joins workers before the public call returns, and drains each failed attempt before retry; parent-scope cancellation of an idle coordinator is observed through the local `scope-cancelled?` runtime predicate. Shared adapters prove generate/stream × abort/per-step plus unconsumed-stream drainage, silent close, stale-registration rejection and bounded tool dispatch (9 tests / 35 assertions) and native OpenAI loopback proves held headers, held SSE body with preserved partial output, held JSON body, normal paced multi-chunk streams and tool continuation with each body closed exactly once and zero surviving workers (3 tests / 67 assertions). Remaining: adapter connect/request/stream-read timeout distinctions, server-observed disconnect witnesses (let-go `http/serve` handlers cannot observe client disconnect, nooga/let-go#831), and noncooperative custom callbacks that ignore the combined abort signal, which are joined indefinitely rather than abandoned. Work inside lazy-seq thunks is not scope-cancelled (nooga/let-go#829) and relies on registered body closers. `SCN-ULLM-CANCEL`. |
| ULLM-TOOLS-01 | done:component | ToolChoice, active/passive tools, execute handlers, bounded multi-step rounds, validation/repair, parallel ordered execution, streaming calls, and continuation messages round-trip through every adapter ([§5](../../../upstream/strongdm-attractor/unified-llm-spec.md#5-tool-calling)). | ULLM-ERROR-01 | done:component | Normalize provider errors and retry status/header/drop conditions with bounded policy. Streaming HTTP error readers retain code/raw/classification and close exactly once (9543aaa): eight tests / 208 assertions plus 13 loopback cases prove all four adapters avoid auth/quota retries, bound rate-limit attempts, and select Retry-After delays; the OpenAI held-error-body case proves eventual abort cleanup. See [stream HTTP errors](../../../stream-http-errors.md). [Terminal streaming errors](../../../stream-terminal-errors.md) adds seven tests / 346 assertions and four held-SSE loopback cases: typed errors terminate without late frames/tools/retries, retain partial output, raise from the final-response accessor, and close the owned body before consuming the tail. Remaining: full status/drop matrix, native deadline behavior, session-level error paths and joined cancellation. `SCN-ULLM-HTTP-ERRORS`. 2026-09-08: `SCN-ULLM-HTTP-ERRORS` complete; malformed/empty success bodies and streams without a finish event now normalize to one non-retryable provider error. |
