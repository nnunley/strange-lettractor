# Codex app-server backend: spec-aligned orchestration

## Intent and authority

Implement Codex as an alternative `CodergenBackend`, using Codex-managed
subscription authentication. Keep the native let-go agent loop and unified LLM
providers independent. The user approved this direction and the following
orchestration mapping on 2026-09-06; this document records implementation
constraints, not a replacement for the upstream specifications.

Sources: pinned `docs/upstream/strongdm-attractor/attractor-spec.md` sections
1.4, 4.8–4.11, 5.3–5.4, 9.6; `coding-agent-loop-spec.md` section 7;
[official app-server documentation](https://learn.chatgpt.com/docs/app-server).
Use schemas generated by the installed Codex version when implementing its wire
protocol; do not assume online examples match every installed version.

## Orchestration contract

- Sequential full-fidelity stages can reuse a compatible backend session through
  the engine's resolved thread identity. Non-full stages start fresh sessions.
- Parallel branches receive cloned context and isolated histories. Even matching
  textual thread IDs must not accidentally share a concurrent backend session
  across branch scopes. Verify current engine ownership before wiring reuse.
- Fan-in consumes explicit outcomes/artifacts; it does not concatenate every
  worker's transcript. Mixed Qwen/Codex handoffs use context and summaries.
- Parent/subagent histories remain separate; messages and results are explicit.
  Manager observation/guard/steering remains the existing pipeline's concern.
- Both backends publish attributed events into the workflow observation stream.
  Observing an event does not automatically put it into another agent's prompt.
- Preserve checkpoint recovery's summary-high first hop after full-fidelity
  interruption. Persistent Codex thread resume must not bypass that policy.

No universal shared transcript, new orchestration DSL, or automatic migration of
native Codex history into Qwen is included.

## Boundaries

1. `attractor.codex.transport`: owns one child process and its stdio lifecycle;
   sends/receives newline-delimited JSON. JSON is only the external protocol;
   internal data and durable records remain EDN. Use native let-go supervision
   for reader, stderr-drain, and lifecycle workers.
2. `attractor.codex.rpc`: owns request IDs, pending responses, initialization,
   unsolicited notifications, server requests, and protocol failure handling.
3. `attractor.codex.backend`: implements the existing `(node prompt ctx)` hook;
   owns thread/turn lifecycle, compatible session reuse, cancellation mapping,
   and terminal outcomes. It does not implement a unified LLM provider.
4. Existing engine/agent integration: scoped session caches and event provenance;
   CLI selection dispatches native vs Codex backend without replacing DOT control
   flow. Native Qwen remains the default development participant.

Prefer a process per independently owned Codex session initially. This isolates
transport failure and forced cancellation; a shared multiplexed process is a
later optimization, not a prerequisite for a common workflow event stream.

## Local transport evidence

On 2026-09-06 the local `/Users/ndn/development/let-go/lg` successfully executed
this duplex probe; the reply was read before closing child stdin:

```clojure
(require '[io :as io])
(let [p (os/exec "/bin/cat")
      in (.StdinPipe p)
      out (.StdoutPipe p)
      r (io/reader out)]
  (.Start p)
  (.WriteString in "transport-probe\n")
  (println (first (io/line-seq r)))
  (.Close in)
  (io/close r)
  (.Wait p))
```

This proves basic duplex access, not cancellation, bounded buffering, or AOT
correctness. `os/sh` buffers output and `os/exec*` inherits process stdin, but
`os/exec` plus existing Go method interop exposes pipes. No let-go runtime patch
is justified by this investigation alone.

## Safety and failure behavior

- Leave credentials with Codex; never copy tokens into workflow state or logs.
  Require subscription mode for this connector; API-key mode and paid fallback
  are not implicit alternatives.
- First live trials use read-only sandboxing, explicit working directories and
  bounded turns/time. Approval requests are explicitly rejected in unattended
  read-only mode; unsupported server requests get protocol errors, never hangs.
- Keep stdout exclusively protocol data. Drain stderr concurrently with bounded,
  redacted diagnostics; do not publish raw account/auth payloads.
- Bound stdout frames to 1 MiB and the inbound queue to 64 frames. Oversized
  frames or queue overflow fail the connection, settle pending requests, and
  close/reap the child; never silently drop protocol messages. Internal consumers
  must be cancellation-aware and must not run arbitrary user callbacks inline.
- Initialization has a 10-second deadline covering startup and handshake.
  Readiness requires the matching successful initialize response followed by a
  successful initialized-notification write. Spawn failure, rejection, malformed
  response, EOF or deadline expiry closes and joins all owned resources. Test
  rejection, a silent live child, oversized unterminated frames and a stalled
  consumer as well as successful handshake ordering.
- Correlate response IDs separately from thread/turn/item IDs. Unknown harmless
  notifications may be ignored; malformed JSON, duplicate terminal responses,
  EOF with pending work, and process failure must resolve waiters as failures.
- Cancellation sends the supported interrupt request, awaits a bounded grace
  interval, then closes/kills and reaps the owned child if needed. Do not emit
  success or pipeline completion until owned workers have joined. Suppress late
  callbacks after session closure; never kill an unrelated shared process.
- Events carry workflow/stage/branch/session provenance plus provider thread,
  turn and item IDs when available. Sequence locally at the observation sink;
  interleaving is not evidence of causal order across independent participants.
- Reusing a textual thread key with incompatible backend/model settings must
  fail explicitly, rather than silently reusing the wrong session.

## Delivery sequence and mechanical evidence

1. Transport and initialization only: fake child tests for duplex framing,
   streaming before exit, stderr pressure, EOF, bounded shutdown and cleanup;
   optional installed-Codex initialize handshake without starting a model turn.
2. Backend turn lifecycle: recorded/fake protocol cases for deltas, completed,
   failed, interrupted and approval-required turns; explicit subscription check;
   read-only live turn with expected output checked automatically.
3. Existing orchestration integration: full-thread sequential reuse, fresh
   non-full sessions, branch isolation including identical thread keys, and
   attributed events from native and Codex backends. Cancellation/failure of
   one participant must not corrupt another's history.
4. Bounded mixed-provider DOT trial: independent Qwen/Codex branches, explicit
   fan-in, held-out executable verification. Record EDN outcomes and attribution;
   model claims are not pass criteria. Add a separate serial full-fidelity trial.

Every slice requires focused tests plus impacted contracts, the default suite,
and AOT verification with the local let-go >=1.12.2. Live tests are opt-in and
separate from deterministic CI. No claim of multi-agent integration is warranted
by the initialization-only slice.
